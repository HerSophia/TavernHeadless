# 前端审美约束（Frontend Aesthetic Constraints）

## 关系与效力

- 本文是 `docs/frontend-vision.md` 的**可执行约束版**：愿景讲"想要什么气质"，本文讲"具体不准做什么、必须做什么"，是可在 PR 中逐条核对的硬门槛。
- 适用范围：`apps/studio`（强制），并推荐用于所有**新建**前端。`apps/web` 作为现役实现可逐步靠拢，不强制一次性改造。
- 冲突时的优先级：对新建前端，本文的"硬性"条目 > 个人偏好；与 `frontend-vision.md` 的设计令牌/基调一致，若措辞冲突以本文更严格者为准。

## 0. 一句话基调

> 我们做的不是 CRUD 后台，而是一台**精密的光学仪器**：简约、优雅、less is more，信息高效可扫读，默认冷峻、聚焦时微光。

---

## 1. 核心原则（不可妥协）

1. **简约（Minimal）**：每个界面只表达必要信息与必要操作；能减则减。
2. **优雅（Elegant）**：克制、对齐、留白得当；细节精致而不喧哗。
3. **Less is more**：默认隐藏次要信息（展开/hover 露出），不堆砌。
4. **信息高效（Information-dense but scannable）**：密度合理偏高，但始终可快速扫读；数据本身即纹理，不靠装饰填充。

---

## 2. 硬性禁止（DON'T）

- **禁止卡片滥用**：不得把每条信息都包成一张卡片；不得用卡片嵌套卡片堆砌层级。
- **禁止大量阴影**：不得用弥散大阴影（如 `shadow-lg/xl/2xl`、多层 drop-shadow）制造层级。
- **禁止丑图标**：不得使用风格不统一、比例失衡、填充杂乱的图标；不得用 emoji 充当 UI 图标。
- **禁止高饱和大色块**：不得用高饱和色（尤其高饱和紫）作为主导背景或大面积填充。
- **禁止炫技动画**：不得有弹跳、旋转、视差等抢注意力的动效；不得长时间转圈 loading。
- **禁止重边框 + 重阴影 + 重圆角"三件套"**叠加制造廉价立体感。
- **禁止信息空洞的留白**：留白服务于呼吸与分组，不是为了好看而把界面拉空。
- **禁止局部补丁式风格**：不得在单个页面私自引入与令牌体系不一致的颜色/间距/字体。

---

## 3. 硬性要求（DO）

- **靠层叠而非阴影建立层次**：用 `1px` 细边框（`border-white/5`~`/10` 或 `border-black/5`）+ 极微弱背景色差切割空间。
- **适度留白**：遵循 8px 垂直节奏；分组之间留白，组内紧凑。
- **数据用等宽字体**：token、ID、JSON、数值、hash 一律 `JetBrains Mono`，对齐成"工业纹理"。
- **图标统一线性 SVG**：以 Lucide 线性图标为基准（它本身就是干净 SVG，满足"审美好的 SVG、无丑图标"）；Lucide 不足时使用风格一致、像素对齐的定制 SVG。
- **键盘优先**：关键操作可键盘完成；提供命令面板/快捷键，不强迫鼠标跳转。
- **加载优先 skeleton**：用骨架屏表达结构，不用长时间 spinner。
- **默认精简、按需展开**：次要字段折叠，hover/展开露出，保持首屏可扫读。

---

## 4. 卡片（Card）使用准则

卡片不是被禁用，而是被**限量**：

- 默认**不**用卡片。优先用"区块 + 1px 分隔/弱边框 + 背景层差"表达分组。
- 仅在以下场景允许卡片：彼此独立、需要并列对比、且有明确边界的对象（如并排版本对比、独立实体摘要）。
- 卡片样式克制：弱边框 + 极弱背景差，**不加大阴影、不加重圆角**（圆角 ≤ 8px）。
- 禁止：列表里每行一张卡、卡中再套卡、为单一对象套多层卡片。

---

## 5. 阴影与层次

- 主层次手段：边框（`1px`）+ 背景色阶（`--app-bg` → `--panel-base` → `--panel-float`）。
- 允许的"阴影"仅限：聚焦态的克制微光（`focus ring` + 极短扩散，accent 色），用于表达"能量流动/聚焦"，不得常驻。
- 禁止：作为默认装饰的弥散投影、卡片投影、悬浮即大投影。

---

## 6. 图标与 SVG

- **基准**：Lucide 线性图标（统一 stroke、统一视觉语言）。它就是"审美好的 SVG"，与"无丑图标"的要求一致。
- **定制 SVG**：当 Lucide 缺失或不够贴切时，使用定制 SVG，但必须与线性风格一致（同 stroke 宽度、同圆角、像素对齐、`currentColor` 着色）。
- **尺寸与笔画**：图标尺寸成体系（如 14/16/20），stroke 统一（如 1.5px）；不混用填充与线性两种风格。
- **禁止**：emoji 当图标、来源混杂的图标包混用、彩色多色图标乱入、比例失衡或模糊位图图标。

---

## 7. 留白与信息密度

- 8px 垂直节奏；列表行高保证连续扫描效率。
- 密度合理偏高：宁可一屏多看有效信息，也不为"高级感"留大片空白。
- 每个面板主操作 ≤ 2 个；更多操作收进溢出菜单/命令面板。
- 次要信息默认折叠或弱化（次文本色、低对比），不与主信息争夺注意力。

---

## 8. 颜色（对齐 frontend-vision §3.2 / §9）

- 双主题（浅/深），不偏向单一模式；以层叠与不透明度建立空间，而非绝对灰度。
- 强调色：低饱和、高亮度的理性连接色（teal/青）为主；语义色固定：成功(绿)/警告(黄)/错误(红)/信息(蓝)，且偏低饱和。
- 令牌驱动：统一使用 `--app-bg`/`--panel-base`/`--panel-float`/`--border-subtle`/`--border-active`/`--signal-*`/`--text-primary`/`--text-secondary`，禁止散落硬编码色值。

---

## 9. 字体与排版（对齐 frontend-vision §3.3）

- 中文 `Noto Sans SC`；英文/数字 `Geist`；数据/代码 `JetBrains Mono`。
- 行高：正文 1.55，面板说明 1.45，标题 1.25。
- 标题不靠超大字号撑场面，靠层级与留白；数值/ID 一律等宽对齐。

---

## 10. 动效

- 仅在状态切换时出现，时长 150~250ms，缓动克制（如 `cubic-bezier(0.2,0,0,1)`）。
- 悬停只改背景/边框，不改布局、不位移。
- 流式文本平滑显现，避免逐字跳动闪烁。
- 禁止：装饰性循环动画、入场炫技、视差。

---

## 11. 组件取舍速查

| 诉求 | 推荐 | 避免 |
| --- | --- | --- |
| 分组层级 | 1px 边框 + 背景色阶 | 卡片堆叠、大阴影 |
| 强调当前项 | 弱背景 + accent 细边/微光 | 高饱和填充、粗描边 |
| 展示数据 | 等宽 + 对齐 + 弱次文本 | 每条包卡片、彩色徽章泛滥 |
| 图标 | Lucide 线性 / 一致定制 SVG | emoji、混风格图标、位图 |
| 加载 | skeleton | 长时间 spinner |
| 操作入口 | ≤2 主操作 + 命令面板/溢出菜单 | 一排按钮糊满面板 |
| 危险操作 | 二次确认 + Impact 预览 | 直接执行、无提示 |

---

## 12. PR 审查清单（前端改动必过）

- [ ] 没有为单条信息滥用卡片；分组优先用边框 + 背景层差。
- [ ] 没有 `shadow-lg/xl/2xl` 等大阴影作装饰；层次靠 1px 边框 + 背景色阶。
- [ ] 图标统一线性 SVG（Lucide 或一致定制 SVG），无 emoji / 混风格 / 位图图标。
- [ ] 颜色全部走设计令牌，无散落硬编码；无高饱和大色块。
- [ ] 数据/ID/token 用 `JetBrains Mono` 且对齐。
- [ ] 留白遵循 8px 节奏，信息可扫读，无空洞留白。
- [ ] 动效 ≤250ms、不改布局、无炫技；加载用 skeleton。
- [ ] 每面板主操作 ≤2，其余收纳。
- [ ] 危险操作有二次确认 / Impact 预览。

---

## 13. 适用与演进

- `apps/studio`：从 v0 起强制遵循，作为"精密光学仪器"调性的样板。
- 其他新建前端：默认遵循。
- `apps/web`：鼓励逐步靠拢，迁移时按本清单收口。
- 本文如与产品演进冲突，应先更新 `frontend-vision.md` 再回写本约束，保持愿景与约束一致。
